About DSP

A platform to make geospatial data more accessible

The DSP — Data Sharing Platform is a generic platform for public consultation of geospatial data. Inspired by the experience of the Rural Environmental Registry Public Consultation (CAR), it was designed so that different organizations can publish, explore, and share their own data through a reusable and configurable solution.

What is the DSP?

The Data Sharing Platform is a generic product designed to turn the public consultation experience for geographic data into a reusable tool for different institutions.

From a domain-specific experience to a reusable platform

The CAR Public Consultation shows how an interface can combine filters, indicators, cartographic visualization, layers, and data publishing. The DSP generalizes that capability so the solution is not limited to a single database or domain.

Instead of relying on territorial values, indicators, or layers fixed in code, a DSP instance can define its own structure by running ./config.sh, which guides configuration and generates config/adopter/adopter-config.yaml.

For example, one instance can use Country → Region → District, while another can use State → Municipality → Area, without changing application logic.

Available features

What can you do with the DSP?

Features for consultation, geospatial exploration, and access to available data.

Hierarchical territorial filters

Support for configurable filters at hierarchical levels and lookup by registration unit or feature identifier.

Dynamic indicators and KPIs

A dashboard with 1 to 5 indicators configured according to the instance fields, labels, and units of measurement.

Map and thematic layers

Configurable layers and territorial divisions, organized into themes and sublayers with visibility control.

Details of the queried unit

Display of identifier, location, area, and registration and update dates after map selection.

Data downloads

Lookup by territory and theme to list available services and formats.

Data-driven updates

Information is refreshed when underlying data changes, with the retrieval date shown. Integration with the RER, a Digital Public Good, enables environmental property registration and timely updates in the DSP.

Platform adaptation

One solution, multiple instances

A new organization can adapt the platform to its own data without rewriting the application for each scenario.

  • Define the territorial structure of your instance.
  • Configure the filters shown to users.
  • Define KPIs, labels, and units of measurement.
  • Organize geographic themes and sublayers.
  • Publish your data through the configured infrastructure.

Frequently asked questions

Understand how the DSP adapts to your context

Is the DSP only for environmental data?

No. The DSP is the continuation of the RER as a generic platform for geospatial data consultation and sharing. The CAR Public Consultation experience served as a reference, but the solution was designed to be reusable.

Do I need to change the code to use a different territorial division?

No. Run ./config.sh to define filters and territorial structure through the guided wizard; the assistant writes these options to config/adopter/adopter-config.yaml.

Can I define my own indicators?

Yes. Run ./config.sh to configure KPIs through the guided wizard; calculated fields, labels, and units are saved in the instance configuration, with support for one to five indicators.

How can I contribute?

Contributions are made through the official GitHub repository. Report issues, propose features, and submit improvements via pull request.
